# Framing And Options

Most bad decisions start with one of three failures: unclear values, a badly framed question, or an impoverished option set.

## Step 0: Clarify Values

Before comparing options, identify what matters enough to guide trade-offs.

Ask:

- What are you optimizing for, really?
- Which principles or values should this decision protect?
- What would make the "best" answer feel wrong anyway?
- Which trade-offs are acceptable, and which violate something important?

Keep this lightweight. The goal is not a philosophy workshop. The goal is to stop hidden values from sneaking into later scoring.

Common value categories:

- autonomy
- stability
- growth
- speed
- craft or quality
- relationships
- integrity
- long-term optionality
- security
- mission alignment

If the decision is between two options with similar surface scores but very different felt meaning, values are probably the real differentiator.

## Step 1: Write The Decision Statement

Turn the problem into one sentence:

`Should [decision owner] [take action A, B, C, pilot, delay, or keep the current path] by [time horizon] in order to [goal]?`

Good framing has:

- a single decision, not three bundled together
- a clear owner
- a concrete horizon
- a baseline option

## Step 2: Separate Goal From Means

Ask:

- What outcome are we actually trying to create?
- Which parts are constraints and which parts are preferences?
- Are we deciding on a goal, a method, or a timing question?

If those are mixed together, split them before evaluation.

## Step 3: Build The Option Set

Always include:

- the obvious options already under discussion
- `do nothing` or `stay the course`
- `delay to learn` if waiting could change the evidence
- `pilot` if reversibility can be improved
- one wildcard if the current set feels too narrow

## Step 4: Define Criteria

Separate criteria into three buckets:

### Must-haves

Fail any of these and the option is out.

Examples:

- budget ceiling
- hard deadline
- compliance or safety requirement
- minimum quality bar

### Weighted criteria

These are the main trade-offs once must-haves are passed.

Good weighted criteria usually translate the values named in Step 0 into decision terms.

Common categories:

- impact or upside
- cost
- speed
- quality
- reversibility
- risk
- strategic fit
- stakeholder acceptance

### Anti-criteria

These are dealbreakers that may not show up cleanly in a score.

Examples:

- creates unacceptable lock-in
- damages trust with key stakeholders
- introduces unmanageable operational burden

## Step 5: Surface Assumptions

List the assumptions that would matter most if they were wrong.

Good prompts:

- What must be true for the favored option to work?
- What are we treating as fact that is really a guess?
- What evidence would most change our mind?

## Framing Fixes

### If the user sounds stuck

- ask what they would choose today if forced
- ask what they are optimizing for
- ask whether the real question is `whether`, `which`, or `when`

### If all options look bad

- add a staged option
- revisit the goal and constraints
- ask if the baseline is actually better than the current framing suggests

### If the choice feels emotional

- preserve the emotional factor as a real criterion
- do not pretend it disappears because a table exists

### If the options are hard to compare because they represent different identities

- ask which value each option honors
- ask which value conflict is actually driving the tension
- if needed, write a simple decision tenet before continuing
