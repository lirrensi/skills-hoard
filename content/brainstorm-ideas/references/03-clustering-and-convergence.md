# Clustering And Convergence

Do not let brainstorming end as a flat list.

The value comes from shaping the space into patterns, candidates, and next moves.

## When To Stop Diverging

You can stop generating when most of these are true:

- you have enough ideas for the stakes
- the set spans multiple mechanisms, not just multiple wordings
- both practical and non-obvious options are present
- new ideas are mostly recombinations of existing clusters
- the next useful move is grouping, not adding more lines

## Clustering Rules

Group ideas into 4-8 meaningful themes.

Cluster by:

- mechanism
- user or stakeholder served
- time horizon
- risk or effort profile
- business model or operating model
- system boundary or leverage point

Name clusters with a clear mechanism.

Good:

- `Guided self-serve onboarding`
- `Human high-touch support`
- `Architecture simplification`

Weak:

- `Better experience`
- `Innovation`
- `Misc`

## Gap Check

After clustering, ask:

- which cluster dominates the set and why
- which user or stakeholder is underrepresented
- whether all ideas sit in the same time horizon
- whether the set is all optimization and no reframing, or all reframing and no execution path

If the space looks lopsided, run one more targeted divergence pass.

## Convergence Levels

Use the lightest level that matches the user's need.

### Level 1: Direction Pick

Use when the user wants a few strong directions, not a scored decision.

Output:

- top 3-5 directions
- why each is promising
- what would need to be true

### Level 2: Quick Prioritization

Use when the user needs a practical shortlist.

Good methods:

- impact vs effort
- must-have filter plus simple ranking
- one-line scorecards on 3-4 criteria

### Level 3: Structured Ranking

Use when the shortlist will drive meaningful work.

Pick 3-5 criteria such as:

- impact
- feasibility
- speed
- risk
- cost
- strategic fit
- learning value
- reversibility

Score consistently and document trade-offs.

### Level 4: Decision Handoff

Use when the user now needs commitment under uncertainty.

At this point, move the best options into `decision-framework` rather than turning brainstorming into fake decision science.

## Selection Heuristics

- do not pick three near-duplicates just because they scored well
- preserve one unconventional option if it opens a distinct upside
- note runners-up that are weaker now but worth revisiting later
- document dependencies, not just scores
- prefer next experiments when confidence is low

## Default Output Shape

Unless the user wants a different format, return:

1. the framed question
2. the mode used
3. the major clusters
4. the top candidates or directions
5. the key trade-offs and unknowns
6. the next experiment, research step, or decision move

## Failure Modes

- stopping at idea count instead of pattern quality
- creating overlapping clusters with vague labels
- scoring without clear criteria
- forcing precision when the brief is still fuzzy
- killing all wild options because they are harder to compare
- treating brainstorming as complete when no next move exists
