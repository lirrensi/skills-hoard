# Part 1 - Structure Pass

Use this file as an operating procedure, not just a reminder list. First diagnose the draft's spine. Then test whether the rest of the piece actually supports it.

This pass checks internal coherence, structural logic, and promise/payoff. It does not judge whether the ideas are correct in the real world unless the text contradicts itself.

## Decision tree

### 1. Find the spine
- If you cannot state the piece's central promise, controlling question, or core claim in one sentence, flag a missing spine.
- If two or more competing promises seem to be fighting for control, flag competing centers of gravity.
- If large chunks of the draft do not serve the apparent spine, flag structural drift.

### 2. Test the opening contract
- If the opening promises a destination, check whether the body actually delivers it.
- If the opening raises a question, check whether the draft answers it.
- If the opening spends time on material that never matters later, flag false setup.

### 3. Test section order
- If you find yourself asking, "Why am I being told this now?" flag sequencing trouble.
- If a point depends on context that arrives later, flag missing setup.
- If a section repeats work another section already did, flag redundancy.
- If a section feels detached from the surrounding sections, test whether it should move, merge, shrink, or disappear.
- If removing a section does not damage what follows, run the cut test and flag it as non-load-bearing, redundant, or misplaced.

### 4. Test setup and payoff
- If the draft introduces a distinction, example, anecdote, object, or concept, check whether it pays off later.
- If the conclusion depends on an idea the body never properly establishes, flag unearned payoff.
- If the draft opens threads and never closes them, flag dangling threads.

### 5. Test internal consistency
- If one section assumes not-X after another section argues X, flag contradiction.
- If key terms shift meaning across the draft, flag term drift.
- If the draft changes level without warning, such as moving from example to thesis to aside without a bridge, flag logical wobble.

### 6. Test the ending
- If the ending merely stops, flag weak closure.
- If the ending restates without advancing, flag low-value conclusion.
- If the ending claims more than the body earned, flag overreach.
- If the ending does not close what the opening opened, flag broken closure.

## Core checklist

### Spine and focus
- [ ] Can the draft's central promise, question, or claim be stated clearly?
- [ ] Does most of the draft serve that spine?
- [ ] Is there one dominant center of gravity rather than multiple competing ones?

### Opening
- [ ] Does the opening establish what the piece is about?
- [ ] Does it create a real contract with the reader?
- [ ] Does the body deliver what the opening sets up?

### Order and shape
- [ ] Does the sequence of sections follow a logic the reader can track?
- [ ] Does each major section earn its place?
- [ ] If a section vanished, would anything meaningful break downstream?
- [ ] Is anything missing that the structure requires?
- [ ] Is anything present that is tangential or redundant?

### Setup and payoff
- [ ] Are important setups later paid off?
- [ ] Does any payoff arrive without enough setup?
- [ ] Are there threads, questions, or distinctions opened and left hanging?

### Consistency
- [ ] Does anything stated in one part contradict another part?
- [ ] Are terms and concepts used consistently?
- [ ] Do shifts in level or scope have enough transition?

### Closing
- [ ] Does the ending close what the opening opened?
- [ ] Does the piece arrive somewhere rather than merely stop?
- [ ] Is the ending earned by the body?

## Severity guide

- `structural break` - the draft's logic, order, or promise is materially broken
- `reader stumble` - the draft basically works, but the reader has to do avoidable repair work
- `optional polish` - the structure holds, but a change would sharpen the piece

## Output rules

- Lead with the 1-3 highest-leverage structural issues.
- Point to a specific location every time.
- Explain the consequence for the reader or for the piece's logic.
- Give revision direction, not just diagnosis.
- You may suggest operations like cut, merge, split, reorder, frame earlier, define sooner, or pay off later.
- Use the cut test when useful: if removing a section changes nothing important, that is evidence the section may not belong in the body.
- You may offer a short example of a stronger transition, claim, or framing move if that helps the writer see the fix.
- Do not rewrite the full section or return replacement prose for the whole piece.

## Do not drift

- Do not turn this pass into a truth debate.
- Do not get lost in sentence-level polish before diagnosing the frame.
- Do not treat interesting tangents as valuable just because they are interesting.
