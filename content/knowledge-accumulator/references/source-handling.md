# Source Handling

## Source classes

Knowledge Accumulator commonly works with:

- public web documentation
- expert interviews or voice notes
- codebases and internal docs
- manuals, specs, and standards
- existing notes or prior corpora
- mixed-source projects

Record these in `source_map.md`.

## What to capture for each source

At minimum, capture:

- source label or title
- source class
- pointer or location
- why it matters
- reliability or trust note if relevant
- status: queued, active, harvested, superseded, or questionable

## Link vs embed

Link when the source is:

- stable
- maintained
- easy to revisit
- useful as a hub to further material

Embed when the source is:

- fragile or likely to disappear
- hard to rediscover
- uniquely sharp about an edge case
- contradictory in a way worth preserving exactly

Always annotate links with one short sentence describing the content, not just the page title.

## Provenance discipline

You do not need a full formal metadata system for every project, but you do need enough provenance that a later agent can answer:

- where did this come from
- why do we trust it or distrust it
- when was it added or last checked
- what part of the taxonomy does it support

## Contradictions

Do not smooth contradictions away.
When sources disagree:

- keep both claims if both matter
- note the disagreement explicitly
- record what would resolve it, if known
- add the conflict to `gaps.md` if it blocks decisions
